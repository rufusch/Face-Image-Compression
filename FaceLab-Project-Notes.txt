FACELAB
Face Image Compression Using Singular Value Decomposition

PROJECT OVERVIEW

FaceLab is a local desktop application for exploring how singular value
decomposition (SVD) approximates an image. It displays the original beside
reconstructions at ranks 100, 50, 25, 10, and 5. Comparing these outputs shows
how broad facial structure and fine detail are affected as fewer components
are retained. The software can also process other supported images.

Research question
How does the number of retained singular values affect reconstruction quality,
visible detail, and the storage needed for the SVD factors?

Objectives
- Represent a grayscale or color photograph as pixel matrices.
- Decompose each channel once and reuse its factors at five ranks.
- Compare reconstructed images visually and numerically.
- Explain the relationship between retained rank, approximation error, and
  storage requirements.
- Explore optional resizing, smoothing, and rank optimization separately.

MATHEMATICAL CONCEPT

An image channel is a matrix A with m rows and n columns. Grayscale uses one
matrix. Color uses separate red, green, and blue matrices. Let p = min(m, n).
The reduced singular value decomposition is

    A = U @ Sigma @ Vt

U has shape m x p, Sigma is a p x p diagonal matrix, and Vt has shape p x n.
Sigma contains nonnegative singular values s[0], ..., s[p-1] in descending
order. The squared singular values are eigenvalues of A.T @ A, and the right
singular vectors are the corresponding eigenvectors.

The rank-r approximation retains the first r singular values and vectors:

    A_r = U_r @ diag(s_r) @ Vt_r
        = sum(s[i] * outer(U[:, i], Vt[i, :]) for i in range(r))

U_r is m x r, s_r contains r diagonal values, and Vt_r is r x n.
Every reconstruction still has m x n pixels. Lower rank means fewer retained
components and usually more visible loss of fine detail.

Before rounding or clipping:

    Squared Frobenius error = sum(s[i]**2 for i >= r)
    Retained energy (%) = 100 * sum(s[:r]**2) / sum(s**2)

The rank-r SVD reconstruction minimizes Frobenius error among matrices of
rank at most r. The gallery quality measurement is calculated after the
reconstruction is converted back to valid pixel values.

    MSE = mean((reference_pixel - reconstructed_pixel)**2)
    PSNR = 10 * log10(255**2 / MSE), in dB

Higher PSNR indicates closer pixel agreement. Exact matches have zero MSE
and are shown as exact matches instead of a finite PSNR.

Key Python operations

    U, s, Vt = svd(A, full_matrices=False)
    A_r = (U[:, :r] * s[:r]) @ Vt[:r, :]
    pixels = np.clip(np.rint(A_r), 0, 255).astype(np.uint8)

The multiplication by s[:r] scales the columns of U_r. This gives the same
result as multiplying by the diagonal matrix without allocating it.

ARCHITECTURE AND DATA FLOW

    main.py starts the desktop application
        -> desktop.py accepts the image and color mode
        -> backend.py decodes the image and builds pixel matrices
        -> SciPy computes SVD once for each channel
        -> NumPy reconstructs the five ranks using the same factors
        -> backend.py measures quality and encodes the factor archives
        -> desktop.py displays results and handles inspection and exports

STORAGE AND COMPRESSION

For one channel, the original matrix contains m*n pixel values. The retained
factors contain m*r + r + r*n = r*(m+n+1) values. Multiply both counts by the
number of channels for the color case.

Pixels use one byte each as uint8. The stored factors use four bytes per
value as float32 before encoding. FaceLab displays the actual encoded NPZ
factor size. The exported PNG contains reconstructed pixels, so its size is
a separate measurement. The size of an uploaded JPEG or PNG is also a
separate measurement because it is already encoded.

Worked theoretical example
For a 256 x 256 grayscale image at rank 10, the original matrix contains
65,536 pixel values. The factors contain 10*(256+256+1) = 5,130 values.
That is 20,520 bytes of float32 factors before encoding, compared with
65,536 bytes of raw uint8 pixels. The measured NPZ size depends on encoding.

EXTENDED MATHEMATICAL METHODS

These experiments are available in the separate analysis interface. The main
five-rank gallery compares reconstructions of the same prepared image.

Rank optimization
    Fit a continuous exponential model to normalized squared SVD error.
    Combine this model with a theoretical factor-storage penalty:

        E_hat(x) = a * exp(-b*x)
        R(x) = 4*x*(m+n+1)/(m*n)
        J_hat(x) = E_hat(x) + lambda*R(x)
        J_hat'(x) = -a*b*exp(-b*x) + lambda*4*(m+n+1)/(m*n)
        J_hat''(x) = a*b*b*exp(-b*x)

    The continuous model illustrates how derivatives locate a minimum.
    Check the valid domain and compare actual costs across integer ranks
    to obtain the final recommendation. A weak model fit can produce a
    different estimate from the measured integer minimum.

Area-average resizing
    Each output pixel averages intensity over its source footprint R:

        I_R = integral over R of f(x,y) dx dy / area(R)

    The implementation treats input pixels as constant over their cells
    and weights each contribution by its overlap with the output footprint.
    Show the source values, overlap weights, and output value before rounding.

Heat-equation denoising
    Add reproducible synthetic noise to a known reference and smooth it
    by solving the two-dimensional heat equation:

        u_t = alpha * (u_xx + u_yy)
        u_new = u + mu * (north + south + east + west - 4*u)

    With unit pixel spacing, mu = alpha*dt. The explicit scheme uses
    mu = 0.2, within its stability bound of 0.25, and zero-flux boundaries.
    Compare clean, noisy, smoothed, and reconstructed images against the
    clean reference. Strong diffusion can remove genuine image detail.
